## [未发布 / Unreleased]

### 命令行 / CLI

- `flowgit prune` 清理旧版本：每个阶段默认保留最新 5 个，并留下所有手动修改、和当前文件一致的最新版本，以及最近一次成功的运行。`--dry-run` 只列出能腾出的空间；不在终端里必须加 `--yes` 才会删除。删掉的版本号不会再被使用。`runs/` 超过 500 MB 时，`flowgit status` 最后一行会提示可以清理。
- `batch <file.csv>`：用一份 CSV 一次做很多份。表头是流程输入的名字，每一行复制一份流程（不带产物、`runs/`、`flowgit.local.json`、`.env*`）再跑完。空单元格用默认值；必填是空的，这一行失败，其他行继续。停在人工阶段记为等待。结束时列出每行的状态和 token，以及合计。退出码：全部完成是 0，有等待且没有失败是 2，有失败是 1。再跑一次不会重新复制已有的文件夹。`--concurrency` 默认 1、最大 4；`--rows a-b` 只跑其中几行。输出目录在流程里面时（默认 `batch/`），复制会跳过它。从 Git 地址复制来的流程先确认一次（`--yes` 不问），做的事一样的副本沿用这次确认。
- `templates --all` 在自带模板之外列出社区模板（`registry/community.json`：在仓库里就用这份文件，否则读 GitHub 上的 raw 地址，`FLOWGIT_REGISTRY` 可以换成别的网址或本地文件），读不到时仍列出自带模板并提示一行。`init -t <社区 id>` 按登记的 Git 地址复制；Git 地址末尾的 `#path=子目录` 和 `--path` 一样。`gallery build` 把静态模板画廊生成到 `gallery-dist/`（每个模板一页：README、阶段图、`init` 命令、依据和 SKILL.md 下载），不部署。
- 回退以后，`flowgit status` 的“版本”一栏显示现在的文件是哪一版，例如 `v2（回退 / restored） /3`；`status --json` 和看板的 `GET /api/flow` 多了 `current`。
- `flowgit serve --mcp` 把流程变成本机 stdio 上的 MCP 服务器，提供 `run_flow`（参数就是流程输入，带 `enum`）、`run_stage`、`get_output` 和 `status`。跑到人工阶段返回要准备的文件和路径，客户端支持 elicitation 时直接问人。有 script、agent、service 或 mcp 阶段的流程要加 `--allow-exec` 才能运行；还没确认的复制流程会被拒绝。`--print-config` 打印 Claude Code、Claude Desktop 和 Cursor 的配置。经过 MCP 的运行在 `run.json` 记下 `via: "mcp"` 和 `client`。说明见 `docs/mcp.md`。
- `flowgit prune` deletes old versions: each stage keeps its newest 5, every manual edit, the newest version matching the current files, and the newest successful run. `--dry-run` only lists how much space that frees; outside a terminal nothing is deleted unless `--yes` is set. Deleted version numbers are never reused. When `runs/` is over 500 MB, the last line of `flowgit status` says so.
- `batch <file.csv>` runs many copies from one CSV. The header row names the flow inputs; each data row is a copy of the flow (without outputs, `runs/`, `flowgit.local.json` or `.env*`) that then runs. Empty cells use defaults; an empty required input fails that row and the others still run. A row that stops at a human stage is waiting. The command ends with each row's state and tokens, then a total. Exit 0 when all are done, 2 when some are waiting and none failed, 1 when any failed. Running it again does not recopy folders that already exist. `--concurrency` defaults to 1 and is at most 4; `--rows a-b` runs only that range. When the output directory is inside the flow (the default `batch/`), the copy skips it. A flow copied from a Git URL is confirmed once first (`--yes` skips the question), and copies that do the same things run under that confirmation.
- `templates --all` lists community templates as well as the bundled ones (`registry/community.json`: the file in a checkout, otherwise the raw file on GitHub; `FLOWGIT_REGISTRY` can point at another URL or a local file), and still prints the bundled ones with one note when that list can't be read. `init -t <community id>` copies the registered Git URL, and `#path=<subdir>` at the end of a Git URL works like `--path`. `gallery build` writes a static template gallery to `gallery-dist/` (a page per template: README, stage graph, `init` command, sources and a SKILL.md download) and does not deploy.
- After a restore, the runs column of `flowgit status` shows which version the files are, e.g. `v2（回退 / restored） /3`; `status --json` and the board's `GET /api/flow` gain `current`.
- `flowgit serve --mcp` serves a flow as a local MCP server over stdio with `run_flow` (its parameters are the flow inputs, with `enum`), `run_stage`, `get_output` and `status`. At a human stage it returns the files to prepare and where; when the client supports elicitation it asks the person directly. A flow with a script, agent, service or mcp stage only runs with `--allow-exec`, and a copied flow that hasn't been confirmed is refused. `--print-config` prints the setup for Claude Code, Claude Desktop and Cursor. Runs made over MCP record `via: "mcp"` and `client` in `run.json`. See `docs/mcp.md`.

### 执行器 / Executors

- JSON 产物不符合 schema 时，自动修复会接着原来的对话：模型能看到原来的提示词和自己完整的回复，只改不合格的地方。以前只把截到 4000 字的回复发回去，长的 JSON 会被改坏，英文流程的修复结果还可能变成中文。回复不是 JSON 而失败时，这次调用的 token 也会记进运行记录。
- `mcp` 执行器可以运行了：调用 MCP 服务器上的一个工具，把结果写成产物。`mcpServers` 的写法和 Claude Desktop / Cursor 一样（stdio 的 `command` / `args` / `env`，或 Streamable HTTP 的 `url`）；`env` 必须是 `${变量名}`，把密钥直接写进 flow.json 会校验失败。一个阶段只有一个产物：文本把 `text` 用空行拼起来，JSON 写入 `structuredContent`（没有就写 `content`），目录把图片和音频存成 `001.png` 这样的文件、文字存成 `result.md`；`isError` 会让阶段失败。`timeoutSec` 默认 60，到点停掉子进程，stderr 记进运行日志。改了工具参数或服务器命令会需要重跑，换密钥的值不会。从 Git 地址复制来的流程，确认之前不会启动 MCP 服务器，`init` 也会列出要启动的服务器。`flowgit doctor` 检查命令和变量，`flowgit mcp tools <服务器>` 列出工具和参数。示例见 `examples/mcp-echo`，说明见 `docs/mcp.md`。
- `plugin` 执行器可以运行了：用流程目录里的插件跑一个阶段。包名只从该目录的 `node_modules` 解析，不自动安装；`./` 路径必须留在流程目录内。插件默认导出 `{ flowgitPlugin: 1, name, executor: { run(ctx) } }`，`ctx` 是 `@flowgit/core` 的 `PluginContext`。`flowgitPlugin` 不是 1 就报错，请升级 Flowgit 或插件。包的 `package.json` 版本（文件夹插件则是文件哈希）和 `config` 算进是否需要重跑。从 Git 地址复制来的流程，确认之前不会加载插件，`init` 也会列出要加载的插件。`flowgit doctor` 和新命令 `flowgit plugins` 列出路径、版本和没装上的插件。示例见 `examples/plugin-echo`，说明见 `docs/plugins.md`。
- `image` 执行器可以运行了：按提示词生图，写进以 `/` 结尾的目录（`001.png` 起）。`model` 写成 `<provider>/<model>`，预设有 OpenAI、智谱 CogView、火山方舟 Seedream、阿里云百炼万相。`each` 按上游 JSON 数组逐张生成。万相会提交任务，马上查一次，之后每 2 秒再查，直到成功、失败或 `timeoutSec`（默认 180）。密钥只从环境变量读。`FLOWGIT_IMAGE_MOCK_DIR` 用本地图片试跑，不调用接口。从 Git 地址复制来的流程，确认之前不会调用生图接口，`init` 也会列出要调用的生图模型。`flowgit providers` 多了「生图 / Image」一节，`flowgit log` 会显示模型、尺寸和张数。自带模板仍默认用上传的素材。示例见 `examples/image-shots`，说明见 `docs/image.md`。
- When a JSON output fails its schema, the automatic repair continues the original conversation: the model sees the original prompt and its whole reply, and changes only what fails. Before, it got the reply cut to 4,000 characters, so long JSON came back broken and an English flow's repair could come back in Chinese. A run that fails because a reply is not JSON now records that call's tokens too.
- The `mcp` executor runs: a stage calls one tool on an MCP server and writes the result as its output. `mcpServers` matches Claude Desktop / Cursor (stdio `command` / `args` / `env`, or a Streamable HTTP `url`); `env` values must be `${VAR}`, and a literal secret in flow.json fails validation. A stage has one output: text joins the `text` items with blank lines, JSON gets `structuredContent` (or `content` when that is absent), and a directory saves images and audio as `001.png` and so on, with text in `result.md`; `isError` fails the stage. `timeoutSec` defaults to 60, then the child process is killed, and its stderr goes to the run log. Changing the tool arguments or the server command marks the stage stale; changing a secret's value does not. A flow copied from a Git URL starts no MCP server until it is confirmed, and `init` lists the servers it would start. `flowgit doctor` checks the command and variables, and `flowgit mcp tools <server>` lists tools and parameters. See `examples/mcp-echo` and `docs/mcp.md`.
- The `plugin` executor runs: a stage runs with a plugin in the flow directory. A package name resolves only from that directory's `node_modules` and is never auto-installed; a `./` path must stay inside the flow directory. The default export is `{ flowgitPlugin: 1, name, executor: { run(ctx) } }`, and `ctx` is `@flowgit/core`'s `PluginContext`. Any `flowgitPlugin` other than 1 is an error asking you to upgrade Flowgit or the plugin. A package's `package.json` version (a hash of the files, for a folder plugin) and `config` count toward staleness. A flow copied from a Git URL loads no plugin until it is confirmed, and `init` lists the plugins it would load. `flowgit doctor` and the new `flowgit plugins` command list the path, version and missing plugins. See `examples/plugin-echo` and `docs/plugins.md`.
- The `image` executor runs: it generates pictures from a prompt into a directory whose path ends with `/` (named from `001.png`). `model` is `<provider>/<model>`, with presets for OpenAI, Zhipu CogView, Volcengine Ark Seedream and Alibaba Cloud Model Studio Wanxiang. `each` makes one picture per item of an upstream JSON array. Wanxiang submits a task, polls once immediately and then every 2 seconds until it succeeds, fails, or `timeoutSec` (default 180) elapses. Keys are read only from environment variables. `FLOWGIT_IMAGE_MOCK_DIR` tries the stage with local pictures and calls nothing. A flow copied from a Git URL calls no image API until it is confirmed, and `init` lists the image models it would call. `flowgit providers` adds a "生图 / Image" section, and `flowgit log` shows the model, size and count. Bundled templates still default to uploaded assets. See `examples/image-shots` and `docs/image.md`.

### 看板 / Board

- 看板界面一次只显示一种语言：右上角「中文 / EN」切换，选择记在浏览器里；第一次打开跟着浏览器语言（中文浏览器显示简体中文，其他显示英文）。文案在 `public/i18n.js`，用开源翻译库 [i18next](https://www.i18next.com)；服务器和流程文件里的双语提示（“中文 / English”）也只显示当前语言那一半。
- The board shows one language at a time: switch with "中文 / EN" at the top right, remembered in the browser; the first visit follows the browser language (Simplified Chinese for a Chinese browser, English otherwise). Strings live in `public/i18n.js` on the open-source [i18next](https://www.i18next.com) library, and bilingual messages from the server and from flow files ("中文 / English") show only the current language's half.
- 看板更有立体感：卡片有分层阴影，高度表示状态（可以运行的浮得最高，等上游的凹下去），编号是立体字，按钮像键帽一样能按下去；用鼠标时，卡片会朝鼠标倾斜，里面的内容分层浮起。流程图默认是 2.5D：阶段是倾斜地面上的方块，可以运行的方块轻轻浮动，通向正在运行阶段的连线会流动；流程图右上角可以切回平面图，选择记在浏览器里。系统打开“减少动态效果”时，倾斜和浮动都会关掉。
- The board has depth: cards have layered shadows and their height shows their state (ready to run floats highest, waiting for upstream sits recessed), stage numbers are extruded, and buttons press down like keys; with a mouse, the card under it tilts toward it and its contents float at different depths. The graph is 2.5D by default: stages are blocks on a tilted floor, a stage that is ready bobs gently, and the edge into the running stage flows; switch back to the flat graph at the top right of the graph, remembered in the browser. Tilting and bobbing turn off when the system asks for reduced motion.
- 回退以后，卡片和阶段面板显示现在的文件是哪一版，例如“v2 · 已回退（最新是 v3）”；历史里这一版标着“当前”，也不再提供“回退到这个版本”。
- After a restore, the card and the stage panel show which version the files are, e.g. "v2 · restored (latest is v3)"; the history marks that version "current" and no longer offers to restore it.
- 卡片上能直接看到产物的样子（最高 120px）：图片原样显示，视频用 ffmpeg 抽第 1 秒的一帧（没有 ffmpeg 就显示视频图标，帧缓存在 `.flowgit/thumbs/`），音频显示波形和时长，文本和 Markdown 显示去掉语法后的前三行，JSON 显示顶层键和数组长度，文件夹显示前四张图和文件数。点缩略图打开原来的产物侧栏。说明超过三行时收起来，点「展开」看全部。新接口 `GET /api/thumb?stage=&output=`。
- Cards show what each output looks like (120px tall at most): the image itself, a frame from 1 second into a video when ffmpeg is available (a video icon when it is not; frames are cached in `.flowgit/thumbs/`), a waveform and duration for audio, the first three lines of text and Markdown with the syntax removed, top-level keys and array lengths for JSON, and the first four images plus a file count for a folder. Clicking a thumbnail opens the existing output panel. Instructions longer than three lines fold until you click "more". New route `GET /api/thumb?stage=&output=`.
- 看板端到端测试：`pnpm test:e2e` 用 Playwright 打开真实看板（不包含在 `pnpm test` 里）。CI 在 Ubuntu 上单独跑。
- Board end-to-end tests: `pnpm test:e2e` opens the real board with Playwright (not part of `pnpm test`). CI runs them on Ubuntu in their own job.
- 看板收到无法解析的请求路径（例如 `//`）时返回 400，不再是 500。
- A request path the board cannot parse (for example `//`) returns 400 instead of 500.

### 模板和示例 / Templates and examples

- `social-posts`：多平台帖子。3 到 5 个角度（人挑选）→ 按小红书、微博、X、抖音、LinkedIn、微信朋友圈已公布的长度和话题规则写帖 → 检查绝对化用语、医疗用语、导流痕迹和占位符（只提醒）→ 导出 `posts.md`。规则会变，发出去之前要再核对。
- `data-report`：数据报告。表格（人，任何带表头的 CSV，中文表头和 Excel 默认的 GBK 编码也行；示例是虚构的销售表）→ 列画像（类型、缺失、唯一值、最小/最大/平均/中位数、日期范围）→ 模型只写柱状、折线或表格的规格，不写代码 → 脚本汇总并手写浅色深色都能看的 SVG → 结论在前、每条发现都引用图 → 合成报告，分析里对不上画像或汇总的数字只警告、不拦截。
- `meeting-notes`：会议纪要。转录（人，`.txt` / `.srt` / `.vtt`，UTF-8 或 GBK）→ 按发言人合并并保留起始时间 → 纪要（每条决定标 `[12:30]`）→ 待办（一人、一事、日期、出处；会上没说负责人或日期就留空，检查会提醒补上）→ 检查（只提醒，格式不对才停下）→ 会后邮件。转录可能有个人信息，分享前要自己看一遍。
- `landing-page`（落地页）按研究加深：简报写上访问者从哪里来、证据、表单和隐私；表单字段有标签、类型、自动填充和必填标记，表单下写明谁收集、做什么用、存多久、怎么撤回，可选的 `privacyUrl` 加上隐私政策链接，同意框不预先勾选；推荐语只用简报里的真实原话；图片带宽和高。检查分成“必须修”（会失败：WCAG 2.2、收集告知、预先勾选、占位、对比度）和“上线前确认”（只提醒：紧迫感、绝对化用语、推荐语原话、简报里没有的数字等）。依据写在模板 README 的“参考资料”里。
- 用 DeepSeek 把自带模板中英文各跑一遍，按评测改了 11 个模板的提示词或检查（报告见 [docs/template-eval.md](docs/template-eval.md)，`node scripts/eval-templates.mjs` 可以复现）：英文流程的每个模型产物都写英文（以前小说的设定和细纲、课程的学员分析会写成中文）；`slides` 不编数字，页数照目标；电商标题删到平台上限以内，英文详情页用英文标签；直播话术不报资料里没有的数字，也不暗示原价；短剧人名不带括号译名；商业计划书的客单价一定是一年的钱；求职材料的关键词用输出语言；多平台帖子的长度和话题写成好数的说法。英文检查报告按数量写单复数。
- `podcast`：播客单集，从选题到上线。资料（人）→ 策划（一句话角度、分段分钟数加起来等于目标、开放式问题和追问、带出处的事实）→ 台本（写给耳朵听，广告第一句先说明）和给嘉宾的录前说明（录音环境、请对方同意录音和发布）→ 录前检查 → 录音和转录（人，`.srt` / `.vtt` / `.txt`）→ 整理文字稿，另存带说话人的 `publish/transcript.vtt` → 节目简介（标题、章节、赞助标明）→ 发布检查（章节按 Apple、Spotify、YouTube 的规则，时间要对得上文字稿；放了音频又装了 FFmpeg 时按 Apple 的建议量响度和真峰值）。检查只提醒。依据写在模板 README 里。
- `picture-book`：绘本或短漫画。创作说明（人）→ 版式（脚本按页数和成书尺寸排好每个跨页或每一页，算出 300 DPI 加出血要多少像素）→ 故事（角色外观、三次尝试、主角自己解决、重复句）→ 分页（每个跨页的字、插图说明、图片描述和翻页钩子；漫画是每页的分格和对白）→ 投稿稿、分页稿、给画家的插画说明和样书 HTML → 画前检查（字数、插图说明重复文字、翻页钩子、讲道理的句子、图片描述长度、漫画对白框的字数）→ 插图（人）→ 成书预览 → 印刷检查（缺图、像素、比例、格式；插图用 AI 生成时列出 KDP、《人工智能生成合成内容标识办法》和美国版权局要求的标识和声明）。检查只提醒。依据写在模板 README 里。
- `product-launch`：新品发布物料包，一份产品资料做出一次发布要用的全部物料。产品资料（人）→ 定位和信息（April Dunford 的五个部分、所有物料共用的发布标题、三条信息支柱，每条说法都带资料原文作出处）→ 发布计划和媒体资料（脚本按发布日期、时区和分级排时间表，把 Product Hunt 的太平洋时间 0:01 换算成你的时区，禁发时写明禁发到哪天几点）→ 新闻稿（倒金字塔，客户原话一字不改并写明关系）→ 发布邮件（主题、预览文字、一个按钮，页脚写发件人、地址和退订）→ Product Hunt 文案（只收英文）、X 和 LinkedIn 帖子 → 对外和内部常见问题（资料答不了的标「待确认」）→ 落地页（子流程，复用 `landing-page`，简报从产品资料生成，页面开头接住发布标题）→ 发布当天的汇总（每一栏带字数，X 按加权算）→ 检查（日期和星期、各平台的字数、资料里没有的数字和网址、客户原话和关系、绝对化用语、要证据的说法、紧迫感、请人点赞、退订和地址）。检查只提醒。依据写在模板 README 里。

### 格式 / Format

- `flow.json` 规范 v0.1：流程输入（可带 `enum`）、阶段、产物和执行器，见 [docs/spec.md](docs/spec.md)。
- JSON 产物可以带 `schema`（一个 JSON Schema 文件）。跑完就检查；llm 不合格时自动让模型修一次。改 schema 文件会让这个阶段需要重跑。短视频模板的分镜带了 `schemas/storyboard.schema.json`。
- 每次运行都存成一个版本：`runs/<阶段>/<n>/` 里有产物快照和 `run.json`，可以随时回退。
- 是否需要重跑由上游产物、流程输入和执行器配置（包括提示词文件和脚本文件）的哈希决定，并向下游传递；手动改过的产物在重跑或回退前会先存成 `manual` 版本，不会被覆盖；回退到的旧版本不算手改。
- 流程也可以写成 `flow.md`：YAML 头写流程信息，每个 `## 阶段名 {#id}` 是一个阶段，配置写在 ```` ```flowgit ```` 代码块里，其余文字就是说明。和 `flow.json` 用同一个规范检查，可以互相转换。
- `flow.json` spec v0.1: flow inputs (optionally with an `enum`), stages, outputs and executors; see [docs/spec.md](docs/spec.md).
- A flow can also be written as `flow.md`: YAML frontmatter for the flow, one `## Stage name {#id}` per stage with its settings in a ```` ```flowgit ```` block, and the rest as descriptions. It is checked against the same spec as `flow.json`, and the two convert into each other.
- A JSON output can carry a `schema` (a JSON Schema file). It is checked when the stage finishes, and an llm stage that fails gets one automatic repair call. Editing the schema file marks the stage stale. The short-video template's storyboard uses `schemas/storyboard.schema.json`.
- Every run is kept as a version: `runs/<stage>/<n>/` holds an output snapshot and `run.json`, and you can roll back at any time.
- Whether a stage needs a re-run comes from a hash of upstream artifacts, flow inputs and executor config (including prompt and script files), and it propagates downstream. A hand edit is saved as a `manual` run before any re-run or restore, so it is never overwritten; a restored older version does not count as a hand edit.

### 执行器 / Executors

- `human`：人来完成，缺产物时流程停下并说明要放什么。
- `llm`：接任何模型。模型写成 `<provider>/<model>`，内置 Anthropic、OpenAI、OpenRouter、智谱 GLM、DeepSeek、Moonshot、通义千问和本机 Ollama，其他兼容 Anthropic 或 OpenAI 接口的服务加一条配置就行。密钥只从环境变量读。每次调用后显示 token 用量，`run all` 调用了好几次时最后再显示合计。自动修复 schema 算两次调用；修复后仍不合格的失败运行也会记下用量。
- `script`：在流程目录执行一条命令；`requires` 列出命令还要用到的程序（例如 `ffmpeg`）。
- `service`：调用 HTTP 服务。`POST` 发送流程输入和 1 MB 以内的文本上游产物，`GET` 把流程输入放进查询参数。请求头用 `{{env.变量名}}` 传密钥，不写进文件；跳转只跟同一个源，不会把请求头带到别的网站。`timeoutSec` 默认 60。示例见 `examples/service-echo`。
- `workflow`（`engine: "flowgit"`）：运行另一份 `flow.json`。`params.inputs` 传给子流程（字符串可用 `{{inputs.名称}}`），`params.copy` 把子流程的产物复制成本阶段的产物。子流程用自己的 `runs/`。子流程停在人工阶段或失败时，父阶段也停或失败。可以嵌套，环和超过 5 层会报错；改子流程的提示词或脚本会让父阶段需要重跑。其他引擎仍是预留。示例见 `examples/subflow`。
- `agent`：以无界面模式启动 Claude Code、Codex、Cursor、Gemini 或自定义的 agent CLI，只用能写流程目录的最小权限。
- `script` 和 `agent` 可以设 `timeoutSec`：到时间就停掉整棵进程树（macOS、Linux 先 `SIGTERM`、5 秒后 `SIGKILL`；Windows 用 `taskkill /T /F`），这次运行记为失败。按 Ctrl+C 时也会一起停掉子进程。
- `human`: done by a person; when outputs are missing the flow stops and says what to put where.
- `llm`: any model. Models are written `<provider>/<model>`, with Anthropic, OpenAI, OpenRouter, Zhipu GLM, DeepSeek, Moonshot, Qwen and local Ollama built in; any other Anthropic- or OpenAI-compatible service is one config entry. Keys are read only from environment variables. Each call shows its token usage, and `run all` ends with a total when it made several calls. A schema repair counts as two calls, and a run that still fails after the repair keeps its usage too.
- `script`: runs a command in the flow directory; `requires` lists other programs the command needs (e.g. `ffmpeg`).
- `service`: calls an HTTP service. `POST` sends the flow inputs and text upstream outputs up to 1 MB; `GET` puts the flow inputs in the query string. Headers pass keys with `{{env.NAME}}`, never written to a file, and redirects are followed only within the same origin so headers never reach another site. `timeoutSec` defaults to 60. See `examples/service-echo`.
- `workflow` (`engine: "flowgit"`): runs another `flow.json`. `params.inputs` are passed to the sub-flow (strings may use `{{inputs.name}}`), and `params.copy` copies sub-flow outputs into this stage's outputs. The sub-flow keeps its own `runs/`. A human wait or a failure in the sub-flow waits or fails the parent too. Nesting is allowed; a cycle or more than 5 levels is an error, and editing a sub-flow prompt or script marks the parent stale. Other engines stay reserved. See `examples/subflow`.
- `agent`: starts Claude Code, Codex, Cursor, Gemini or a custom agent CLI headless, with the least permission that still lets it write in the flow directory.
- `script` and `agent` take `timeoutSec`: when it runs out, the whole process tree is stopped (`SIGTERM`, then `SIGKILL` after 5 seconds on macOS and Linux; `taskkill /T /F` on Windows) and the run is recorded as failed. Ctrl+C stops the child processes too.

### 命令行 / CLI

- `init`、`templates`、`validate`、`status`（终端看板）、`board`（网页看板）、`inputs`、`run`、`log`、`diff`、`restore`、`providers`、`doctor`、`graph`、`export-skill`。
- `init -t` 可以是 Git 地址（`git clone --depth 1`，可加 `--ref` 和 `--path`）。从本地目录或 Git 复制时默认不带产物，`--with-outputs` 才带上；Git 来源会把 `forkedFrom` 写进新的 `flow.json`。没有安装 git 时会说明怎么装。
- `convert --to md|json` 在 `flow.json` 和 `flow.md` 之间转换，内容不变；`init --format md` 新建时直接用 `flow.md`。`stage add`、`stage rm` 写回时保持原来的格式。
- `stage add` / `stage rm`：用命令加、删阶段。llm 和 agent 没给提示词时会建一个中英双语骨架，已有文件不覆盖。删阶段不删文件，也不动 `runs/`；还有别的阶段依赖它时要 `--force`。
- `share`：把流程复制成可以分享的副本。先检查密钥（发现就拒绝、什么都不写）、邮箱和本机路径（写完后提醒）。`runs/`、`flowgit.local.json`、`.env*` 和 `.flowgit/` 永远不复制。
- `doctor` 在运行前检查 Node、流程输入、密钥、代理设置，以及脚本和 agent 要用的命令。
- 用代理或 VPN 时自动连得上模型：`run` 和 `board` 会走 `HTTPS_PROXY`，不用再设 `NODE_USE_ENV_PROXY=1`；Windows 和 macOS 上打开了系统代理也会自动用上。`doctor` 显示用的是哪个代理，`FLOWGIT_PROXY=off` 可以关掉。
- `export-skill` 把流程导出成 `SKILL.md`，AI 工具不用界面也能按步骤运行。
- `graph` 把流程画成 Mermaid 流程图，贴进 GitHub 或 Obsidian 就能看到；加 `--status` 按状态上色，`-o/--out` 直接写成 UTF-8 文件（`.md` 自动包上代码块）。
- `log` 不写阶段时按时间列出整个流程的所有版本，并合计用掉的 token。
- `diff` 对比同一个阶段的两个版本，或者某个版本和现在的文件：文本和 JSON 显示按行的改动，二进制只比较是否相同，文件夹列出新增、删除和改动的文件。
- `board` 在浏览器打开本机看板（新包 `@flowgit/web`）：每个阶段一张卡，显示状态、最新版本和产物，点产物在侧栏预览文本、JSON、图片、视频和目录。文件一变就通过 SSE 的 `flow:changed` 刷新（约 300 毫秒合并一次）；保存产物、上传、运行结束、回退和保存输入也会推送。连接着的时候不再每 3 秒轮询，断开时提示并改回每 3 秒刷新，每 5 秒重连。文本产物可以直接修改保存（JSON 先检查格式），人工阶段的文件夹可以上传文件；改过的产物下次运行前会先存成一个版本。可以填写流程输入，运行单个阶段或全部阶段，日志实时显示；同时只跑一个，运行中不能保存产物。每张卡可以看历史版本、对比两个版本（或和当前文件比）并回退。只监听 `127.0.0.1`，接口要令牌并检查 `Host`。
- 看板换了新造型：亮色是粗网格加大号阶段编号，可以运行的那一步整块变蓝；暗色是深色卡片，状态用发光圆点标出。跟着系统的深浅色自动切换，不用联网加载字体。
- 看板上可以新增和删除阶段。校验不通过就什么都不写，并返回双语错误列表；llm / agent 没有提示词文件时会建骨架，已有文件不覆盖。删除不碰产物和 `runs/`，还有依赖时会说明并可以一起断开。运行中不能改阶段。
- 看板上可以在「卡片 / Cards」和「流程图 / Graph」之间切换，选择记在浏览器里。流程图按依赖从左到右分列，阶段是圆角框，颜色和卡片一样表示状态；点一个阶段，侧栏里可以看产物、运行和历史。布局来自 `GET /api/graph`（`layoutFlow`）。
- 看板上有「预演 / Preview」：在日志里列出每个阶段会跳过、运行、等你还是不能运行，最后写最多调用几次模型，什么都不运行。全部运行前，如果这次会调用真实模型（`FLOWGIT_LLM_MOCK_DIR` 的固定回复不算），会先确认。每张卡片和流程图方框的提示显示这个阶段用过的 token，页面顶部显示合计。`GET /api/plan` 和 `GET /api/usage`。
- 看板加了五个动效（拆解自 Awwwards 上的作品；系统打开“减少动态效果”时全部关掉）：状态变化时，新状态像解码一样逐字显出来；「全部运行」要按住 1 秒，按住时每张卡片和流程图方框上先标出这个阶段会跳过、运行、等你还是不能运行，按满才运行，提前松手什么都不运行（轻点和以前一样，会调用真实模型时先确认），「预演」的结果也会标在卡片和流程图上（Esc 收起）；运行时正在跑的阶段标成「运行中」，看板自动滚到它；侧栏从点的位置圆形展开，关闭时收回同一个点；历史版本排成一叠唱片，可以拖、甩或用方向键翻，最前面那张可以看产物、和当前文件对比或回退。
- `run all --dry-run` 预演：每个阶段会跳过、运行还是停下等你，最多调用几次模型，什么都不运行。`doctor` 通过后和导出的 `SKILL.md` 里都会提到它。
- `inputs set` 保存前就检查名字和值（数字、`true`/`false`、可选值），写错了不会存进去。
- `board` 打印和打开的链接带着令牌（`?token=…`）。直接打开 `http://127.0.0.1:4747/` 只会看到提示、拿不到令牌，所以同一台电脑上的其他账号或程序没法操作你的看板。
- 从 Git 地址或别的文件夹 `init` 时，会列出这个流程要运行的命令、要启动的 agent 和要调用的服务（以及请求头里带的环境变量），运行前先看一眼。
- 从 Git 地址复制来的流程，第一次运行前要在这台电脑上确认一次它会做的事（包括子流程里的命令）：`run` 会列出来再问，`flowgit trust` 可以先确认，`run --yes` 不问直接确认，看板上会弹窗。确认记在 `~/.flowgit/trusted.json`，不在流程目录里；这些命令变了会再问。
- 提示词文件，以及要发给模型或服务的上游产物，如果是指向流程目录外面的链接，就不读取（`validate` 也会报出来），免得下载来的流程把 `~/.ssh` 这类文件发出去。脚本和 agent 阶段不受影响。
- 流程自己的 `flowgit.local.json` 改了某个带密钥的模型服务的地址时，`doctor` 会警告，运行日志也会写出来，因为密钥会发到那个地址。
- 提示、报错和 `--help` 都是中英双语（包括输错命令、少写参数这类报错，会提示“是不是想输入 …”），并针对余额不足、限流、连不上（包括代理）给出具体建议。
- `init`, `templates`, `validate`, `status` (terminal board), `board` (web board), `inputs`, `run`, `log`, `diff`, `restore`, `providers`, `doctor`, `graph`, `export-skill`.
- `init -t` accepts a Git URL (`git clone --depth 1`, with `--ref` and `--path`). Copying a local directory or a Git URL leaves outputs behind unless `--with-outputs` is set, and a Git source writes `forkedFrom` into the new `flow.json`. If git is not installed, the error says how to install it.
- `stage add` / `stage rm`: add or remove a stage from the command line. An llm or agent stage without a prompt gets a bilingual skeleton, and an existing file is never overwritten. Removing a stage deletes no files and leaves `runs/` alone; `--force` is required when other stages depend on it.
- `share` copies a flow into a directory that is safe to hand to someone else. A secret blocks the write entirely; emails and local paths are listed afterwards. `runs/`, `flowgit.local.json`, `.env*` and `.flowgit/` are never copied.
- `doctor` checks Node, flow inputs, keys, proxy settings, and the programs script and agent stages use, before a run.
- Models are reachable behind a proxy or VPN: `run` and `board` use `HTTPS_PROXY` without `NODE_USE_ENV_PROXY=1`, and pick up the Windows or macOS system proxy too. `doctor` shows which proxy is used; `FLOWGIT_PROXY=off` turns this off.
- `export-skill` exports a flow as a `SKILL.md`, so AI tools can run it step by step without the UI.
- `graph` draws the flow as a Mermaid diagram that GitHub and Obsidian render; `--status` colors it by state, and `-o/--out` writes a UTF-8 file (a `.md` file gets the code block).
- `convert --to md|json` switches between `flow.json` and `flow.md` without changing the flow; `init --format md` starts a flow as `flow.md`. `stage add` and `stage rm` write back in the file's own format.
- `log` without a stage lists every version of the whole flow by time and adds up the tokens used.
- `diff` compares two versions of a stage, or a version with the current files: line changes for text and JSON, same-or-different for binaries, and added, removed and changed files for folders.
- `board` opens a local board in the browser (new package `@flowgit/web`): one card per stage with its state, latest version and outputs; click an output to preview text, JSON, images, video or a folder in a side panel. A file change refreshes it through the SSE event `flow:changed` (debounced by about 300 ms); saving an output, an upload, the end of a run, a restore and saving inputs push it too. While that stream is connected it no longer polls every 3 seconds; if the stream drops it says so, polls every 3 seconds again, and retries every 5 seconds. Text outputs can be edited and saved (JSON is checked first), and files can be uploaded into a human stage's folder; an edited output is saved as a version before the next run. Flow inputs can be filled in, and one stage or the whole flow can be run with a live log; one run at a time, and outputs cannot be saved while it runs. Each card can list its versions, compare two of them (or one with the current files) and restore one. It listens on `127.0.0.1` only, and its API needs a token and checks `Host`.
- The board has a new look: in light mode a bold grid with large stage numbers, and the stage you can run now in a solid blue block; in dark mode graphite cards with glowing status dots. It follows the system light/dark setting and loads no web fonts.
- Stages can be added and removed on the board. A stage that fails validation is not written, and the error list is bilingual; an llm or agent stage without a prompt file gets a skeleton, and an existing file is left as it is. Removing a stage leaves outputs and `runs/` in place, names any stages that still depend on it, and can detach those links. Stages cannot be changed while a run is in progress.
- The board switches between "卡片 / Cards" and "流程图 / Graph", and the choice is remembered in the browser. The graph lays stages out left to right by dependency, as rounded boxes colored the same way as the cards; click a stage for its outputs, run, and history in the side panel. Layout comes from `GET /api/graph` (`layoutFlow`).
- The board has "预演 / Preview": the log lists whether each stage would be skipped, run, wait for you or cannot run, and ends with at most how many model calls, without running anything. Run all asks first when the run would call a real model (canned replies from `FLOWGIT_LLM_MOCK_DIR` do not count). Each card and the graph box tooltip show the tokens that stage has used, and the top of the page shows the total. `GET /api/plan` and `GET /api/usage`.
- The board has five motion effects (taken apart from Awwwards sites; all of them turn off when the system asks for reduced motion): a new state decodes into place letter by letter; "全部运行 Run all" is held for one second, and while you hold it every card and graph box shows whether that stage would be skipped, run, wait for you or cannot run, the run starts when the hold completes, and letting go early runs nothing (a quick tap works as before and asks first when it would call a real model), and "预演 / Preview" marks the cards and the graph the same way (Escape clears them); the running stage is marked "运行中 running" and the board scrolls to it; the side panel opens as a circle from where you clicked and closes back into the same point; and a stage's history is a stack of discs you drag, flick or flip with the arrow keys, with the front one ready to open, compare with the current files, or restore.
- `run all --dry-run` shows whether each stage would be skipped, run or stop for you, and at most how many model calls it would make, without running anything. `doctor` points to it when nothing blocks, and so does the exported `SKILL.md`.
- `inputs set` checks names and values (numbers, `true`/`false`, allowed values) before saving, so a typo is never stored.
- The link `board` prints and opens carries the token (`?token=…`). Opening `http://127.0.0.1:4747/` by itself shows a note and no token, so other accounts or programs on the same computer can't drive your board.
- `init` from a Git URL or another folder lists the commands the flow runs, the agents it starts and the services it calls (with the environment variables their headers send), so you can look before you run it.
- A flow copied from a Git URL must be confirmed once on each computer before its first run, with what it does (sub-flow commands included) listed: `run` lists it and asks, `flowgit trust` confirms ahead of time, `run --yes` confirms without asking, and the board asks in a dialog. The confirmation lives in `~/.flowgit/trusted.json`, never in the flow directory, and is asked again when those commands change.
- A prompt file, or an upstream output on its way to a model or a service, that is a link to a file outside the flow directory is not read (`validate` reports it too), so a downloaded flow can't send files like `~/.ssh` anywhere. Script and agent stages are not affected.
- When a flow's own `flowgit.local.json` changes the address of a model provider that sends a key, `doctor` warns and the run log says so, because the key goes to that address.
- Messages, errors and `--help` are bilingual (including typos in commands and missing arguments, with a “did you mean …”), with specific advice for an empty balance, rate limits and connection problems (including proxies).

### 模板和示例 / Templates and examples

- `short-video`（默认）：脚本 → 配音 → 分镜 → 素材 → 剪辑 → 导出。FFmpeg 渲染竖屏视频，支持推近、模糊背景、渐变文字卡、标题、转场、背景音乐和配音（镜头时长跟着配音走）；输出语言可选中文或英文。
- 配音阶段调用 OpenAI 兼容的语音接口，把口播合成 `voice/voice.mp3`。密钥用 `FLOWGIT_TTS_API_KEY`（不写进文件），`FLOWGIT_TTS_BASE_URL` 可以换成别的兼容服务。没配密钥就跳过，不报错；`assets/` 里自己录的配音优先。`doctor` 没配密钥时只提醒，不算错误。
- `weekly-report`：周报入门示例，随手记（人）→ 草稿（模型）→ 检查（脚本），配合 [教程](docs/guide.md) 一步步做出来。
- `article`：图文帖子，大纲 → 正文 → 配图方案 → 照片（人）→ 导出 `post.md` 和 `post.html`。篇幅和语气按平台（小红书、公众号、博客）变化，缺的照片用画面描述占位。
- `support-sop`：客服 SOP，资料（人）→ 汇总（脚本）→ 规程 → 用例 → 检查（模型）→ 打包成 `skill/SKILL.md` 和评测用例。
- `job-application`：对照职位描述改简历并写求职信。简历和求职信并行，最后脚本检查关键词、篇幅和占位符。
- `research-report`：把题目拆成子问题、收集资料、写成带引用的报告。脚本检查没被引用的来源、不存在的引用、没被回答的子问题和没有出处的段落。
- `ecommerce-listing`：电商商品上架（淘宝、拼多多、抖店、亚马逊）。商品资料（人）→ FABE 卖点 → 标题 → 主图和“好处先行”的详情页、客服问答（并行）→ 检查：按平台口径算标题长度（亚马逊 75 个字符）、《广告法》的绝对化和医疗用语、价格比较，以及资料里找不到的数字。README 列出参考资料。
- `slides`：PPT 演示稿。按金字塔原理定核心结论和 SCQA 开场 → 每页“结论标题 + 证据”（图表、画面、引用、步骤，带 schema）→ 排成网页幻灯片 `slides.html` 和讲稿，打印就是一页一张的 PDF → 检查标题、字数、要点页占比和结尾的下一步。
- `live-selling`：直播带货脚本。商品资料（人）→ 七段流程表（留人、痛点、塑品、信任、价格、逼单、返场）→ 逐段话术和弹幕问答（并行）→ 按《网络直播营销管理办法》检查虚构的销量、库存和数字，以及绝对化、医疗用语和价格比较。
- `short-drama`：竖屏微短剧。设定和人物 → 分集节拍（钩子、压抑、爆发、悬念，付费卡点）→ 逐集剧本 → 按广电总局管理提示和创作标准审读 → 检查集数、估算时长、旁白开头、悬念和付费卡点。
- `lesson-plan`：老师备课，按逆向设计。教学目标（布鲁姆层级）→ 评价任务 → 教案和分层练习（并行）→ 学生练习单和答案，并检查教学评一致性、时间和“双减”作业时长。
- `novel-serial`：网文连载。设定和卖点（金手指和它的代价、读者会追着看的“期待”）→ 分章细纲（每章冲突、爽点和章末钩子）→ 黄金三章正文 → 检查字数、爽点断档、没推进的期待、金手指出场和背景式开头。
- `business-plan`：商业计划书，按红杉的结构。公司资料（人）→ 自下而上的市场规模和竞争 → 单位经济和三年预测 → BP 正文 → 检查结构、市场规模乘法、LTV:CAC 和回本月数、资金用途、资料外的数字和承诺回报的说法。
- `event-plan`：活动策划方案。SMART 目标 → 流程表、预算和风险登记表（并行）→ 完整方案 → 检查流程时间、预算算术和预备金、风险类别，以及 1000 人以上公开活动的安全许可。
- `hiring`：招聘流程。岗位需求（人）→ 岗位分析 → 招聘启事和结构化面试题（并行，带 1/3/5 分行为锚点）→ 面试评分表，并检查启事和面试题里的就业歧视风险和脑筋急转弯。
- `travel-guide`：旅行攻略。备选地点（标出要预约和要核实的信息）→ 按区域排的每日行程（交通、留白、雨天备选）→ 攻略笔记 → 检查节奏、时间衔接、预算和出发前核实清单。
- `online-course`：知识付费课程，按 ADDIE。学员和学习成果 → 大纲（每段视频 6 分钟以内、每课有练习）→ 试听课逐字稿和课程介绍页（并行）→ 检查成果覆盖、分段长度，以及介绍页里的效果承诺、学员证言和价格比较。
- 每个新模板的 README 都列出参考资料。
- `landing-page`：落地页。简报（人）→ 结构 → 文案 → 照片（可空）→ 生成 `site/index.html` 和 `site/style.css` → 检查。缺图用色块加说明，页面不访问网络，用户写的文字都会转义。
- `examples/agent-page`：用 agent 做一页介绍网页（只在仓库里）。
- `examples/subflow`：题目（人）→ 子流程（模型和脚本）→ 摘要（脚本）。演示 `workflow` 执行器。
- `short-video` (default): script → voiceover → storyboard → assets → edit → export. FFmpeg renders a vertical video with zoom, blurred fill, gradient text cards, a title, transitions, background music and voiceover (clips follow the voice); the output language is Chinese or English.
- The voice stage calls an OpenAI-compatible speech API and writes `voice/voice.mp3`. The key is `FLOWGIT_TTS_API_KEY` (never written to a file); `FLOWGIT_TTS_BASE_URL` points it at another compatible service. With no key the stage skips instead of failing, and a voiceover you recorded in `assets/` wins. `doctor` warns when the key is missing, and that warning is not an error.
- `weekly-report`: a starter that turns rough notes (person) into a draft (model) and checks it (script); the [guide](docs/guide.md) builds it step by step.
- `article`: an illustrated post, outline → draft → image plan → photos (person) → export to `post.md` and `post.html`. Length and tone follow the platform (Xiaohongshu, WeChat, blog), and a missing photo becomes a placeholder with its scene description.
- `support-sop`: a customer-support SOP, knowledge (person) → collect (script) → SOP → test cases → review (model) → packaged as `skill/SKILL.md` with an eval set.
- `job-application`: tailor a resume and write a cover letter for a job description. The resume and letter run in parallel, then a script checks keywords, length and placeholders.
- `research-report`: split a topic into sub-questions, gather sources and write a cited report. A script checks uncited sources, citations of missing files, unanswered sub-questions and paragraphs with no citation.
- `ecommerce-listing`: a product listing for Taobao, Pinduoduo, Douyin shops or Amazon. Product facts (person) → FABE selling points → titles → main images and a benefit-first detail page, plus customer Q&A (in parallel) → checks on title length counted the platform's way (75 characters on Amazon), absolute and medical claims under China's Advertising Law, price comparisons, and numbers the facts do not contain. The README lists its sources.
- `slides`: a slide deck. A governing thought and SCQA opening (Pyramid Principle) → claim-plus-evidence slides (charts, visuals, quotes, steps; with a schema) → an HTML deck `slides.html` plus speaker notes that prints to a one-slide-per-page PDF → checks on titles, text, bullet share and the closing next step.
- `live-selling`: a live-selling stream script. Product facts (person) → a seven-part rundown (hook, pain, demo, trust, price, close, recap) → segment script and chat Q&A (in parallel) → checks for invented sales, stock and numbers under China's live-stream marketing rules, plus absolute and medical claims and price comparisons.
- `short-drama`: a vertical micro-drama. Story bible and characters → episode beats (hook, suppression, payoff, cliffhanger, paywall) → scripts → a read against NRTA guidance and craft standards → checks on count, length, voice-over openings, cliffhangers and the paywall.
- `lesson-plan`: lesson prep with backward design. Objectives (Bloom levels) → assessment tasks → lesson plan and tiered exercises (in parallel) → a student worksheet and answer key, with checks on alignment, timing and homework load under the double-reduction rules.
- `novel-serial`: a serialized web novel. Setting and hook (the hero's edge and its cost, the expectations readers follow) → chapter outlines (conflict, payoff and closing hook for each) → the first three chapters → checks on length, payoff droughts, stalled expectations, when the edge appears, and openings that start with background.
- `business-plan`: a business plan on Sequoia's outline. Company facts (person) → bottom-up market size and competition → unit economics and a three-year projection → the plan → checks on structure, the market-size multiplication, LTV:CAC and payback, the use of funds, numbers not in the facts, and promised returns.
- `event-plan`: an event proposal. SMART objectives → run of show, budget and risk register (in parallel) → the full proposal → checks on timing, budget arithmetic and contingency, risk categories, and the safety permit for public events of 1,000 or more.
- `hiring`: structured hiring. The role (person) → job analysis → job ad and structured interview questions (in parallel, with 1/3/5 behavioral anchors) → an interview scorecard, with checks for discrimination risk and brainteasers.
- `travel-guide`: a travel guide. Candidate places (flagging bookings and facts to verify) → a day-by-day itinerary by area (transfers, free time, rainy-day backups) → the guide → checks on pace, timing, budget and the check-before-you-go list.
- `online-course`: an online course with ADDIE. Learners and outcomes → syllabus (video segments of six minutes or less, practice in every lesson) → the trial lesson script and the course page (in parallel) → checks on outcome coverage, segment length, and promised results, testimonials and price comparisons on the page.
- Every new template's README lists its references.
- `landing-page`: a landing page. Brief (person) → structure → copy → photos (optional) → build `site/index.html` and `site/style.css` → check. A missing image becomes a color block with a caption, the page loads nothing from the network, and user text is escaped.
- `examples/agent-page`: a one-page explainer made by an agent (repo only).
- `examples/subflow`: topic (person) → sub-flow (model and script) → summary (script). Shows the `workflow` executor.
