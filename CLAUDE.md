# Flowgit

开源工具：把任何过程变成可视化、分阶段、有版本的流程（"万物皆可流程化"）。

Open-source tool for turning any process into a visual, staged, versioned flow ("万物皆可流程化").

## 语言 / Language

- GitHub 上的一切都写中英双语，中文在前：提交信息、PR 标题和说明、README、文档、这个文件。代码标识符和代码注释可以只写英文。
- 命令行的提示和报错也是中英双语（"中文 / English"）。
- 模板生成的内容（提示词、脚本输出、字幕）不强制双语，由流程输入 `language`（`zh` | `en`）决定。

- Everything on GitHub is bilingual, Chinese first: commit messages, PR titles and descriptions, README, docs, and this file. Code identifiers and code comments may stay English-only.
- CLI messages and errors are bilingual too ("中文 / English").
- What a template produces (prompts, script output, captions) is not forced bilingual; the `language` flow input (`zh` | `en`) picks the language.

## 结构 / Layout

- `packages/core`（`@flowgit/core`）：flow.json 的 schema（流程也可以写成 `flow.md`，由 `src/flowmd.ts` 和 flow.json 互转；`schema/flow.schema.json` 是唯一标准，`src/types.ts` 跟它保持一致）、校验、`runs/<stage>/<n>/` 下的运行历史、阶段执行器（`human`、`llm`、`script`、`agent`、`service`、`mcp`、`plugin`、`image` 可运行；`workflow` 在 `engine` 为 `flowgit` 时运行子流程，其他引擎预留）。core 读写文件、哈希、运行命令、发请求、读环境变量都经过 `src/host/` 的 `Host` 接口（`host()` 取当前的，`setHost()` / `withHost()` 换掉）：`host/node.ts` 用 `node:fs` 和 `node:child_process`，`host/memory.ts` 把文件放在内存里（测试和浏览器用，默认不能运行命令）。共享模块不能直接导入 `node:` 模块或用 `Buffer`、`process`；只在电脑上有意义的放 Node 入口（`index.ts` 先导入 `node-setup.ts`：设置 Node Host、注册 `mcp` 执行器、接上代理检测；`doctor.ts`、`proxy.ts`、`executors/mcp.ts`、`executors/command.ts`）。浏览器入口是 `src/browser.ts`（`package.json` 的 `browser` 条件），`pnpm --filter @flowgit/core check:browser` 用 esbuild 打包它，导入了 `node:` 模块就失败（CI 里跑）。flow.schema.json 由 `scripts/gen-schema.mjs` 生成进 `src/flow-schema.generated.ts`，并用 ajv 的 standalone 模式预编译成 `src/flow-validate.generated.ts`（`pnpm build` 会先跑），测试会检查它们是最新的；运行时不能用 `new Function` 编译 flow.json 的 schema（网页版的 CSP 禁止）。产物的 JSON Schema 默认用 ajv 编译，`setSchemaCompiler()` 可以换掉。vitest 用 `vitest.config.ts` 的 `setupFiles` 加载 `node-setup.ts`。
- `packages/cli`（`flowgit`）：commander 命令行在 `src/index.ts`，新命令放 `src/commands/<名字>.ts`，`index.ts` 只加一行注册；自带模板在 `templates/`。`flowgit serve --mcp`（`src/commands/serve-mcp.ts`）用 `@modelcontextprotocol/sdk` 在 stdio 上把流程变成 MCP 服务器（`run_flow`、`run_stage`、`get_output`、`status`），stdout 只走 MCP，给人看的写 stderr；有 script、agent、service、mcp 阶段要 `--allow-exec`，没确认的复制流程直接拒绝；经过 MCP 的运行在 `run.json` 记 `via: "mcp"` 和 `client`。
- `packages/app`（`@flowgit/app`，不发布到 npm）：网页版，静态网站。`scripts/build.mjs` 把 `packages/web/public` 的看板模块原样复制进 `dist/`，从看板的 `index.html` 生成 `board.html`（加上 `static/board-bar.html` 和 `board-shell.js`），再用 esbuild 按 `browser` 条件打包 `src/`；模板打包成 `dist/templates/<id>.json`。看板的 `api.js` 发现 `globalThis.flowgitTransport` 时把请求交给它：`src/router.ts` 的 `BrowserBoard` 在页面里回答 `/api/*`（状态码和返回体跟 `packages/web/src/routes` 一样，`flowBoard` / `flowGraph` 直接复用），`src/events.ts` 代替 SSE。文件在内存 Host 的 `/flows/<id>` 下，每次改动排队写进 OPFS（`src/storage.ts`），改动类请求和 `run:end` 要等写完才返回。key 只放内存，用户勾选才存 localStorage（`src/keys.ts`），永远不写进流程文件。页面的 CSP（`build.mjs` 里的 `CSP`）不允许 eval 和第三方脚本，`connect-src` 只有 DeepSeek、Anthropic、只读的 GitHub 和本机看板（127.0.0.1 / localhost）（`src/import.ts`：公开仓库复制成带 `forkedFrom` 的流程、zip 导入导出，用 fflate）；所以产物 schema 用 `@cfworker/json-schema`（`src/schema.ts`）。电脑上的文件夹（`folder-<名字>`）用 File System Access：`src/folders.ts` 把目录句柄记在 IndexedDB，`src/folder.ts` 的 `folderStore` 读写文件夹（跳过 `.git`、`node_modules`、`.flowgit`），`watchFolder` 在保存队列里轮询外面的改动、静默写进内存 Host 并发 `flow:changed`；`src/folder.test.ts` 用真实文件夹和真实命令行测试互通。要在电脑上运行的阶段可以交给本机看板（`src/handoff.ts`）：用户粘贴 `flowgit board` 的链接（只接受 127.0.0.1 / localhost，令牌只放内存），`BrowserBoard` 的 `remote` 选项把这些阶段的 `POST /api/run` 转给它；只在文件夹流程、而且两边 `GET /api/flow` 的阶段和版本一致时才转，跑完立刻读一次文件夹。存在浏览器里的流程可以“存到文件夹”（`board-shell.ts`）。`pnpm test:e2e:app` 用 Playwright 在浏览器里跑 weekly-report。
- `packages/web`（`@flowgit/web`）：本机看板，可查看、修改和运行阶段，也可填写流程输入、看历史、对比和回退，并在卡片和流程图之间切换（流程图默认用 CSS 3D 画成 2.5D 方块，可切回平面 SVG，选择存在 localStorage）。`node:http` 只绑定 `127.0.0.1`，静态页面在 `public/`（看板是浏览器原生 ES 模块，入口 `app.js`；动效在 `fx.js`，包括卡片跟着鼠标倾斜的 `tilt` 和流程图地面的 `orbit`，比 `app.js` 先加载，遵守减少动态效果的设置；卡片浮起用 `top` 而不是 `transform`，因为卡片菜单是 `position: fixed`；界面文案在 `i18n.js` 的中英两份词典里，经 i18next（`/vendor/i18next.js`，来自依赖包）翻译，一次只显示一种语言，新增或修改界面文字时两份词典都要改），`flowgit board` 打开它；页面只在带 `?token=` 的链接里拿到令牌（`startBoard` 返回的 `url` 就是它）。文本产物用 `PUT /api/file` 保存；人工阶段的文件夹产物用 `POST /api/upload` 上传。`POST /api/run` 在进程里调用 `runStage` / `runAll`（同时只跑一个，忙时 409；运行中保存产物或回退也是 409）。`GET /api/events` 用查询参数 `token` 推送 SSE（运行日志，以及文件变化时的 `flow:changed`）。`GET` / `PUT /api/inputs` 读写流程输入，保存前按 `loadFlowInputs` 的规则校验。`GET /api/runs?stage=` 调用 `listRuns`；`GET /api/diff?stage=&a=&b=` 调用 `diffRuns`（省略 `b` 则和当前文件比）；`POST /api/restore` 的 JSON `{ "stage", "n" }` 调用 `restoreStage`。从 Git 地址复制来、还没确认的流程，`POST /api/run` 返回 409 和 `trust`（`reason`、`source`、`fingerprint`、`actions`），什么都不运行；页面列出 `actions` 让人确认，再把 `fingerprint` 发给 `POST /api/trust`（调用 `trustFlow`；流程在这期间变了就返回 409 和新的 `trust`，什么都不记）。`POST /api/stage` 的 JSON 就是 `addStage` 的参数（`id`、`type`，以及可选的 `name`、`after`、`inputs`、`outputs`、`prompt`、`run`、`agent`），通过后按 `flowgit validate` 校验；有错误就返回 400 的双语列表并且什么都不写，llm 的提示词文件不存在时会建和 `flowgit stage add` 一样的骨架。`DELETE /api/stage?id=<id>` 调用 `removeStage`（`force=1` 才断开下游依赖）；还有依赖且没带 `force` 时返回 409 并点名这些阶段，不删 `runs/` 和产物。运行中这两个接口也返回 409。`POST /api/generate` 调用 `generateFlow`（和 `flowgit new` 相同）：先返回预演和 `id`，带 `{ "confirm": true, "id" }` 再调用才写入（`routes/generate.ts`，前端 `public/generate.js`；网页版里隐藏）；不覆盖已有的流程和文件，运行中返回 409。`GET /api/graph` 调用 `layoutFlow`，返回 `{ nodes: [{ id, name, type, state, layer, row }], edges: [{ from, to }] }`。层按 `topoOrder` 计算：一个阶段的层是它上游里最高的层加 1，同一层的 `row` 不重复。`GET /api/plan?model=` 调用 `planRunAll`（`model` 可省略），返回每个阶段的 `action`、`detail`、`callsModel`，以及 `modelCalls`（这次最多调用几次模型；`FLOWGIT_LLM_MOCK_DIR` 的固定回复不算）。`GET /api/usage` 调用和 `flowgit log`（不写阶段）相同的 `flowLog`，按阶段合计每个版本 `run.json` 里的 token，并返回总计。`GET /api/thumb?stage=<id>&output=<index>` 返回卡片缩略图：图片是原文件并带 `ETag`（svg 的 `Content-Security-Policy` 为 `sandbox`）；有 ffmpeg 时把视频第 1 秒的帧缓存成 `.flowgit/thumbs/<内容哈希>.jpg`，没有则返回 204；有 ffprobe 时音频返回时长。除 SSE 外，`/api/*` 都要带请求头 `X-Flowgit-Token`；`startBoard` 的 `allowOrigins`（默认只有网页版的 `https://flowgit.dev`，命令行 `--allow-origin` 可以加）里的网页可以跨域调用这些接口（预检和 Private Network Access 头在 `server.ts` 的 `crossOrigin`），仍然要令牌。
- `docs/spec.md`：给人看的规范，改 schema 时一起改。
- `docs/guide.md`：入门教程，照着做出自带的 `weekly-report` 模板（`packages/cli/templates/weekly-report`）。里面贴了真实的命令行输出，改了命令行输出或格式时要跟着改。
- `examples/`：只在仓库里的示例流程。它们和 `packages/cli/templates/` 里的模板都由 `packages/core/src/examples.test.ts` 校验。发布流程见 `docs/releasing.md`。
- `site/`：官网落地页（`index.html`，静态页面，中英双语）。#121 会把它和模板画廊、文档合成整个站，部署到 flowgit.dev。
- `CHANGELOG.md`：每个版本的更新记录。用户能感觉到的改动，在最上面的“未发布 / Unreleased”版本下加一行，中英双语。

- `packages/core` (`@flowgit/core`): the flow.json schema (a flow may also be a `flow.md`, converted to and from flow.json by `src/flowmd.ts`; `schema/flow.schema.json` is the source of truth; `src/types.ts` mirrors it), validation, run history under `runs/<stage>/<n>/`, and stage executors (`human`, `llm`, `script`, `agent`, `service`, `mcp`, `plugin`, and `image` run; `workflow` runs a sub-flow when `engine` is `flowgit`, and other engines stay reserved). Core reads and writes files, hashes, runs commands, makes requests and reads environment variables only through the `Host` interface in `src/host/` (`host()` returns the current one; `setHost()` / `withHost()` swap it): `host/node.ts` uses `node:fs` and `node:child_process`, and `host/memory.ts` keeps files in memory (for tests and the browser; it can't run commands by default). Shared modules must not import `node:` modules or use `Buffer` or `process`; desktop-only code belongs to the Node entry (`index.ts` first imports `node-setup.ts`, which sets the Node host, registers the `mcp` executor and plugs in proxy detection; plus `doctor.ts`, `proxy.ts`, `executors/mcp.ts`, `executors/command.ts`). The browser entry is `src/browser.ts` (the `browser` condition in `package.json`); `pnpm --filter @flowgit/core check:browser` bundles it with esbuild and fails if it imports a `node:` module (CI runs it). flow.schema.json is generated into `src/flow-schema.generated.ts` and precompiled with ajv's standalone mode into `src/flow-validate.generated.ts` by `scripts/gen-schema.mjs` (`pnpm build` runs it first), and a test checks both are current; nothing may compile the flow schema with `new Function` at run time (the web app's CSP forbids it). Output JSON Schemas are compiled by ajv by default, and `setSchemaCompiler()` swaps that. vitest loads `node-setup.ts` through `setupFiles` in `vitest.config.ts`.
- `packages/cli` (`flowgit`): the commander CLI in `src/index.ts`; a new command goes in `src/commands/<name>.ts` and `index.ts` only registers it; bundled templates in `templates/`. `flowgit serve --mcp` (`src/commands/serve-mcp.ts`) serves a flow as an MCP server over stdio with `@modelcontextprotocol/sdk` (`run_flow`, `run_stage`, `get_output`, `status`); stdout is only for MCP, and anything for people goes to stderr; script, agent, service and mcp stages need `--allow-exec`, and an unconfirmed copied flow is refused; runs made over MCP record `via: "mcp"` and `client` in `run.json`.
- `packages/app` (`@flowgit/app`, not published to npm): the web app, a static site. `scripts/build.mjs` copies the board modules from `packages/web/public` into `dist/` unchanged, makes `board.html` from the board's `index.html` (adding `static/board-bar.html` and `board-shell.js`), and bundles `src/` with esbuild under the `browser` condition; templates become `dist/templates/<id>.json`. The board's `api.js` hands requests to `globalThis.flowgitTransport` when it exists: `BrowserBoard` in `src/router.ts` answers `/api/*` in the page (statuses and bodies as in `packages/web/src/routes`, reusing `flowBoard` / `flowGraph`), and `src/events.ts` replaces SSE. Files live under `/flows/<id>` on a memory host and every change is queued into OPFS (`src/storage.ts`); change requests and `run:end` wait until those writes finish. Keys stay in memory and go to localStorage only when the person ticks remember (`src/keys.ts`), never into flow files. The page's CSP (`CSP` in `build.mjs`) forbids eval and third-party scripts, and `connect-src` lists only DeepSeek, Anthropic, read-only GitHub and the local board (127.0.0.1 / localhost) (`src/import.ts`: public repositories copied as flows with `forkedFrom`, and zip import and export through fflate), so output schemas use `@cfworker/json-schema` (`src/schema.ts`). A folder on the computer (`folder-<name>`) goes through File System Access: `src/folders.ts` keeps directory handles in IndexedDB, `folderStore` in `src/folder.ts` reads and writes the folder (skipping `.git`, `node_modules` and `.flowgit`), and `watchFolder` polls for outside changes inside the save queue, writes them quietly into the memory host and sends `flow:changed`; `src/folder.test.ts` tests the round trip with a real folder and the real CLI. Stages that need a computer can be handed to the local board (`src/handoff.ts`): the person pastes the `flowgit board` link (127.0.0.1 / localhost only; the token stays in memory), and `BrowserBoard`'s `remote` option forwards those stages' `POST /api/run` to it, only for a folder flow whose stages and versions match the board's `GET /api/flow`, then reads the folder at once. A flow kept in the browser can be saved to a folder (`board-shell.ts`). `pnpm test:e2e:app` runs weekly-report in a browser with Playwright.
- `packages/web` (`@flowgit/web`): the local board, where stages can be viewed, edited, and run, flow inputs can be filled in, history can be browsed, compared, and restored, and the view switches between cards and a flow graph (2.5D blocks in CSS 3D by default, or a flat SVG, kept in localStorage). `node:http` binds `127.0.0.1` only, static files live in `public/` (native browser ES modules, entered from `app.js`; motion in `fx.js`, including `tilt` for the card under the mouse and `orbit` for the graph's floor, loaded before `app.js`, honoring reduced motion; a card lifts with `top`, not `transform`, because its menu is `position: fixed`; UI strings live in the zh and en dictionaries in `i18n.js`, translated through i18next (`/vendor/i18next.js`, from the dependency), one language at a time, so a new or changed UI string goes in both dictionaries), and `flowgit board` opens it; the page only gets the token through the link with `?token=` (the `url` that `startBoard` returns). Text outputs are saved with `PUT /api/file`; files are uploaded into a human stage's directory output with `POST /api/upload`. `POST /api/run` calls `runStage` / `runAll` in-process (one run at a time; 409 when busy, and for output writes or a restore during a run). `GET /api/events` is the SSE stream (the run log, and `flow:changed` when files change) and takes the token in the `token` query parameter. `GET` / `PUT /api/inputs` read and save flow inputs, validated with the same rules as `loadFlowInputs`. `GET /api/runs?stage=` calls `listRuns`; `GET /api/diff?stage=&a=&b=` calls `diffRuns` (omit `b` to compare with the current files); `POST /api/restore` with JSON `{ "stage", "n" }` calls `restoreStage`. For a flow copied from a Git URL that hasn't been confirmed, `POST /api/run` returns 409 with `trust` (`reason`, `source`, `fingerprint`, `actions`) and runs nothing; the page lists the `actions` for the person to confirm, then sends the `fingerprint` to `POST /api/trust` (calls `trustFlow`; if the flow changed meanwhile it returns 409 with the new `trust` and records nothing). `POST /api/stage` takes the `addStage` spec (`id`, `type`, and optional `name`, `after`, `inputs`, `outputs`, `prompt`, `run`, `agent`) and then validates like `flowgit validate`; errors return 400 with a bilingual list and write nothing, and a missing llm prompt file is created the same way `flowgit stage add` creates it. `DELETE /api/stage?id=<id>` calls `removeStage` (`force=1` detaches downstream); without `force`, dependents yield 409 and are named, and `runs/` and output files are left in place. Both routes return 409 during a run. `POST /api/generate` calls `generateFlow` (the same as `flowgit new`): it first returns a dry run and an `id`, and writes only on a second call with `{ "confirm": true, "id" }` (`routes/generate.ts`, front end `public/generate.js`; hidden in the web app); it never overwrites an existing flow or file, and returns 409 during a run. `GET /api/graph` calls `layoutFlow` and returns `{ nodes: [{ id, name, type, state, layer, row }], edges: [{ from, to }] }`. Layers follow `topoOrder`: a stage's layer is one more than the highest layer among its upstreams, and `row` is not repeated inside a layer. `GET /api/plan?model=` calls `planRunAll` (`model` is optional) and returns each stage's `action`, `detail` and `callsModel`, plus `modelCalls` (how many model calls the run would make at most; canned replies from `FLOWGIT_LLM_MOCK_DIR` do not count). `GET /api/usage` calls `flowLog`, the same function as `flowgit log` with no stage, sums the tokens recorded in every version's `run.json` per stage, and returns an overall total. `GET /api/thumb?stage=<id>&output=<index>` is the card thumbnail: an image is the file itself with an `ETag` (svg uses `Content-Security-Policy: sandbox`); with ffmpeg a video's frame at 1 second is cached as `.flowgit/thumbs/<content hash>.jpg`, and without ffmpeg the route returns 204; with ffprobe an audio file returns its duration. Every `/api/*` route except the SSE stream requires the `X-Flowgit-Token` header; pages from `startBoard`'s `allowOrigins` (by default only the web app's `https://flowgit.dev`; the CLI adds more with `--allow-origin`) may call those routes cross-origin (preflight and Private Network Access headers in `crossOrigin` in `server.ts`), still with the token.
- `docs/spec.md`: the human-readable spec. Change it together with the schema.
- `docs/guide.md`: the starter tutorial; it builds the bundled `weekly-report` template (`packages/cli/templates/weekly-report`). It quotes real CLI output, so update it when CLI output or the format changes.
- `examples/`: repo-only example flows. They and the templates in `packages/cli/templates/` are validated by `packages/core/src/examples.test.ts`. Releasing is in `docs/releasing.md`.
- `site/`: the website landing page (`index.html`, a static bilingual page). #121 combines it with the template gallery and the docs into the whole site, deployed to flowgit.dev.
- `CHANGELOG.md`: what changed in each version. For a user-visible change, add a bilingual line under the top "Unreleased" version.

## 命令 / Commands

```bash
pnpm install
pnpm build       # 编译所有包；命令行端到端测试跑的是 dist/ / tsc for every package; the CLI e2e test runs dist/
pnpm typecheck
pnpm test        # vitest；没有 ffmpeg 时跳过渲染测试 / vitest; the render test is skipped when ffmpeg is missing
node scripts/pack-smoke.mjs   # 像发布一样打包并安装后试跑（需要先 build）/ pack, install and run like a release (after build)
pnpm test:e2e:app  # Playwright 打开网页版（需要先 build）/ Playwright on the web app (after build)
pnpm test:e2e    # Playwright 打开真实看板（需要先 build，第一次先 pnpm exec playwright install chromium）/ Playwright on the real board (after build; first run pnpm exec playwright install chromium)
```

## 约定 / Conventions

- llm 阶段默认模型是 `claude-opus-5-5`，通过 `@anthropic-ai/sdk` 流式调用，带 `fallbacks: "default"`。设置 `FLOWGIT_LLM_MOCK_DIR=<dir>` 时改用目录里的固定回复 `<stageId>.md|json`（测试和模板的 `demo-replies/` 用它）。
- 模型写成 `<provider>/<model>`（`src/providers.ts`），只支持 Anthropic 和 OpenAI 两种协议。Claude 专用参数只发给 `api.anthropic.com`。密钥只从 `apiKeyEnv` 指定的环境变量读，不写进任何文件；新增预设时 `baseUrl` 必须来自官方文档，并在注释里附链接。
- `agent` 执行器在流程目录里以无界面模式启动 agent CLI（`src/executors/agent.ts`），提示词走 stdin。内置适配只用"能在流程目录写文件"的最小权限，**永远不默认加跳过所有权限的参数**；每个参数都要照官方文档写并附链接。测试用假的 `custom` agent，不调用真的 CLI。
- `image` 执行器按提示词生图（预设在 `src/image-providers.ts`，执行器在 `src/executors/image.ts`）。模型写成 `<provider>/<model>`。设置 `FLOWGIT_IMAGE_MOCK_DIR=<dir>` 时改为复制 `<dir>/<阶段 id>/` 里的图片（张数不够就循环），不调用接口。
- 手动改过的阶段产物永远不会被覆盖：重跑或回退前先存成一个 `manual` 版本。
- 从 Git 地址复制来的流程（有 `forkedFrom`）如果会运行命令、启动 agent、调用服务、启动 MCP 服务器、加载插件、调用生图接口或运行子流程，`runStage` / `runAll` 在确认前抛出 `TrustNeededError`，什么都不运行（`src/trust.ts`）。确认的是 `flowActions(flow, dir)` 的哈希，存在 `~/.flowgit/trusted.json`（`FLOWGIT_HOME`），永远不存进流程目录；子流程跟着父流程的确认走。测试要把 `FLOWGIT_HOME` 设成临时目录。
- 是否需要重跑 = 上游产物 + 流程输入 + 执行器配置（包括提示词文件、命令里提到的脚本文件，以及 `flowgit` 子流程的 `flow.json` 和它点名的提示词、脚本）的哈希，并向下游传递。
- 流程输入可以带 `enum` 限定取值，运行前会检查。
- 看板的前端模块只通过 `packages/web/public/api.js` 访问后端；除了这个文件，`public/` 里不能调用 `fetch` 或 `EventSource`。网页版也靠这一点换掉后端，所以新接口要在 `packages/app/src/router.ts` 里也实现（做不到就返回和本机看板一样形状的错误）。
- 新的产物查看器放在 `packages/web/public/viewers/`，用 `registerViewer(outputType, viewer)` 注册（`panel.js` 导出这个函数）。

- The default model for llm stages is `claude-opus-5-5`, called through `@anthropic-ai/sdk` with streaming and `fallbacks: "default"`. `FLOWGIT_LLM_MOCK_DIR=<dir>` replaces the model with canned replies `<stageId>.md|json` (used by tests and the template's `demo-replies/`).
- Models are `<provider>/<model>` (`src/providers.ts`), over two protocols only: Anthropic and OpenAI. Claude-only parameters go to `api.anthropic.com` only. Keys are read only from the env var named by `apiKeyEnv` and never written to a file; a new preset's `baseUrl` must come from the vendor's official docs, linked in a comment.
- The `agent` executor starts an agent CLI headless in the flow directory (`src/executors/agent.ts`), with the prompt on stdin. Built-in adapters use the least permission that still lets the agent write files in the flow directory and **never pass a bypass-all-permissions flag by default**; every flag comes from the official docs, linked in a comment. Tests use a fake `custom` agent, never a real CLI.
- The `image` executor generates pictures from a prompt (presets in `src/image-providers.ts`, executor in `src/executors/image.ts`). The model is `<provider>/<model>`. `FLOWGIT_IMAGE_MOCK_DIR=<dir>` copies pictures from `<dir>/<stage id>/` instead (cycling if there are too few) and calls nothing.
- A hand edit of a stage's outputs is never overwritten: it is saved as a `manual` run before any re-run or restore.
- A flow copied from a Git URL (it has `forkedFrom`) that runs commands, starts agents, calls services, starts MCP servers, loads plugins, calls an image API or runs sub-flows makes `runStage` / `runAll` throw `TrustNeededError` before anything runs until it is confirmed (`src/trust.ts`). The confirmation is a hash of `flowActions(flow, dir)` stored in `~/.flowgit/trusted.json` (`FLOWGIT_HOME`), never in the flow directory; a sub-flow runs under its parent's confirmation. Tests must point `FLOWGIT_HOME` at a temp directory.
- Staleness = hash of upstream artifacts + flow inputs + executor config (incl. the prompt file, script files named in the command, and a `flowgit` sub-flow's `flow.json` plus the prompt and script files it names), and it propagates downstream.
- Flow inputs can carry an `enum` of allowed values, checked before a run.
- Front-end board modules reach the back end only through `packages/web/public/api.js`; no other file in `public/` may call `fetch` or `EventSource`. The web app swaps the back end at that one point, so a new route is also implemented in `packages/app/src/router.ts` (or answers with an error shaped like the local board's).
- New output viewers live in `packages/web/public/viewers/` and register with `registerViewer(outputType, viewer)` (exported from `panel.js`).
